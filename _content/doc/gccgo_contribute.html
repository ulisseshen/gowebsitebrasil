Introdução

Estas são algumas notas sobre contribuir para o frontend gccgo para GCC. Para informações sobre contribuir para partes do Go que não sejam gccgo, veja Contribuindo para o projeto Go. Para informações sobre construir gccgo para você mesmo, veja Configurando e usando gccgo. Para mais detalhes técnicos sobre o processo de fazer desenvolvimento com o frontend gccgo, veja o arquivo HACKING no repositório gofrontend.

Pré-requisitos Legais

Você deve seguir as regras de copyright do Go para todas as mudanças no frontend gccgo e na biblioteca libgo associada. Código que faz parte do GCC em vez de gccgo deve seguir as regras gerais de contribuição do GCC.

Código

As fontes mestras para o frontend gccgo podem ser encontradas em https://go.googlesource.com/gofrontend. Elas são espelhadas em https://github.com/golang/gofrontend. As fontes mestras não são compiláveis por si mesmas, mas apenas em conjunto com o GCC (no futuro, outros compiladores podem ser suportados). Mudanças feitas no frontend gccgo também são aplicadas ao repositório de código fonte do GCC hospedado em gcc.gnu.org. No repositório gofrontend, o diretório go é espelhado para o diretório gcc/go/gofrontend no repositório GCC, e o diretório libgo do gofrontend é espelhado para o diretório libgo do GCC. Além disso, o diretório test do repositório principal do Go é espelhado para o diretório gcc/testsuite/go.test/test no repositório GCC.

Mudanças nesses diretórios sempre fluem das fontes mestras para o repositório GCC. Os arquivos nunca devem ser alterados no repositório GCC exceto alterando-os nas fontes mestras e espelhando-os.

O frontend gccgo é escrito em C++. Ele segue os padrões de codificação GNU e GCC para C++. Ao escrever código para o frontend, siga a formatação do código circundante. Quase todo o código específico do GCC não está no frontend propriamente dito e está em vez disso nas fontes do GCC no diretório gcc/go.

A biblioteca de runtime para gccgo é principalmente a mesma da biblioteca no repositório principal do Go. O código da biblioteca no repositório Go é periodicamente mesclado no diretório libgo/go do gofrontend e então nos repositórios GCC, usando o script shell libgo/merge.sh. Consequentemente, a maioria das mudanças na biblioteca devem ser feitas no repositório principal do Go. Os arquivos fora de libgo/go são específicos do gccgo; dito isso, alguns dos arquivos em libgo/runtime são baseados em arquivos em src/runtime no repositório principal do Go.

Testes

Todos os patches devem ser testados. Um patch que introduz novas falhas não é aceitável.

Para executar a suite de testes gccgo, execute make check-go em seu diretório de build. Isso executará vários testes sob gcc/testsuite/go.* e também executará a testsuite libgo. Esta cópia dos testes do repositório principal do Go é executada usando o script DejaGNU encontrado em gcc/testsuite/go.test/go-test.exp.

A maioria dos novos testes deve ser submetida ao repositório principal do Go para posterior espelhamento no repositório GCC. Se houver necessidade de testes específicos para gccgo, eles devem ir nos diretórios gcc/testsuite/go.go-torture ou gcc/testsuite/go.dg no repositório GCC.

Submetendo Mudanças

Mudanças no frontend Go devem seguir o mesmo processo que para o repositório principal do Go, apenas para o projeto gofrontend e a lista de email gofrontend-dev@googlegroups.com em vez do projeto go e a lista de email golang-dev@googlegroups.com. Essas mudanças serão então mescladas nas fontes do GCC.
