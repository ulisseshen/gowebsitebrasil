Introdução

Coberto neste tutorial:

  • Criar uma estrutura de dados com métodos load e save
  • Usar o package net/http para construir aplicações web
  • Usar o package html/template para processar templates HTML
  • Usar o package regexp para validar entrada do usuário
  • Usar closures

Conhecimento assumido:

  • Experiência em programação
  • Compreensão de tecnologias web básicas (HTTP, HTML)
  • Algum conhecimento de linha de comando UNIX/DOS

Começando

No momento, você precisa ter uma máquina FreeBSD, Linux, macOS ou Windows para executar Go. Usaremos $ para representar o prompt de comando.

Instale Go (veja as Instruções de Instalação).

Estruturas de Dados

Vamos começar definindo as estruturas de dados. Uma wiki consiste em uma série de páginas interconectadas, cada uma com um título e um corpo (o conteúdo da página). Aqui, definimos Page como uma struct com dois campos representando o título e o corpo.

{{code "part1.go" `/^type Page/` `/}/`}}

O tipo []byte significa "um slice de byte". (Veja Slices: uso e internals para mais sobre slices.) O elemento Body é um []byte em vez de string porque esse é o tipo esperado pelas bibliotecas io que usaremos, como você verá adiante.

A struct Page descreve como os dados da página serão armazenados na memória. Mas e quanto ao armazenamento persistente? Podemos resolver isso criando um método save em Page:

{{code "part1.go" `/^func.*Page.*save/` `/}/`}}

A assinatura deste método diz: "Este é um método chamado save que recebe como receptor p, um ponteiro para Page. Ele não recebe parâmetros e retorna um valor do tipo error."

Este método salvará o Body da Page em um arquivo de texto. Por simplicidade, usaremos o Title como nome do arquivo.

O método save retorna um valor error porque esse é o tipo de retorno de WriteFile (uma função da biblioteca padrão que escreve um slice de bytes em um arquivo). O método save retorna o valor do erro, para permitir que a aplicação o trate caso algo dê errado ao escrever o arquivo. Se tudo correr bem, Page.save() retornará nil (o valor zero para ponteiros, interfaces e alguns outros tipos).

O literal inteiro octal 0600, passado como terceiro parâmetro para WriteFile, indica que o arquivo deve ser criado com permissões de leitura-escrita apenas para o usuário atual. (Veja a página de manual Unix open(2) para detalhes.)

Além de salvar páginas, também queremos carregar páginas:

{{code "part1-noerror.go" `/^func loadPage/` `/^}/`}}

A função loadPage constrói o nome do arquivo a partir do parâmetro title, lê o conteúdo do arquivo em uma nova variável body e retorna um ponteiro para um literal Page construído com o título e corpo apropriados.

Funções podem retornar múltiplos valores. A função da biblioteca padrão os.ReadFile retorna []byte e error. Em loadPage, o erro ainda não está sendo tratado; o "identificador em branco" representado pelo símbolo underscore (_) é usado para descartar o valor de retorno do erro (em essência, atribuindo o valor a nada).

Introduzindo o package net/http (um interlúdio)

Aqui está um exemplo funcional completo de um servidor web simples:

{{code "http-sample.go"}}

A função main começa com uma chamada a http.HandleFunc, que diz ao package http para tratar todas as requisições para a raiz web ("/") com handler.

Ela então chama http.ListenAndServe, especificando que deve escutar na porta 8080 em qualquer interface (":8080"). (Não se preocupe com seu segundo parâmetro, nil, por enquanto.) Esta função bloqueará até que o programa seja terminado.

ListenAndServe sempre retorna um erro, pois só retorna quando um erro inesperado ocorre. Para registrar esse erro, envolvemos a chamada da função com log.Fatal.

A função handler é do tipo http.HandlerFunc. Ela recebe um http.ResponseWriter e um http.Request como seus argumentos.

Um valor http.ResponseWriter monta a resposta do servidor HTTP; ao escrever nele, enviamos dados para o cliente HTTP.

Um http.Request é uma estrutura de dados que representa a requisição HTTP do cliente. r.URL.Path é o componente de caminho da URL da requisição. O [1:] no final significa "criar um sub-slice de Path do 1º caractere até o final." Isso remove a "/" inicial do nome do caminho.

Se você executar este programa e acessar a URL: 

http://localhost:8080/monkeys

o programa apresentaria uma página contendo: 

Hi there, I love monkeys!

O package html/template

O package html/template faz parte da biblioteca padrão do Go. Podemos usar html/template para manter o HTML em um arquivo separado, permitindo-nos alterar o layout da nossa página de edição sem modificar o código Go subjacente.

A função template.ParseFiles lerá o conteúdo de edit.html e retornará um *template.Template.

O método t.Execute executa o template, escrevendo o HTML gerado para o http.ResponseWriter. Os identificadores pontilhados .Title e .Body referem-se a p.Title e p.Body.

A instrução printf "%s" .Body é uma chamada de função que produz .Body como uma string em vez de um stream de bytes, o mesmo que uma chamada a fmt.Printf. Como você pode ter observado, este programa tem uma falha de segurança séria: um usuário pode fornecer um caminho arbitrário para ser lido/escrito no servidor. Para mitigar isso, podemos escrever uma função para validar o título com uma expressão regular.

Primeiro, adicione "regexp" à lista de import. Então podemos criar uma variável global para armazenar nossa expressão de validação:

A função regexp.MustCompile analisará e compilará a expressão regular, e retornará um regexp.Regexp. MustCompile é distinta de Compile pois ela entrará em pânico se a compilação da expressão falhar, enquanto Compile retorna um error como segundo parâmetro.

Introduzindo Literais de Função e Closures

Capturar a condição de erro em cada handler introduz muito código repetido. E se pudéssemos envolver cada um dos handlers em uma função que faz essa validação e verificação de erro? Os literais de função do Go fornecem um meio poderoso de abstrair funcionalidade que pode nos ajudar aqui.

Primeiro, reescrevemos a definição de função de cada um dos handlers para aceitar uma string de título: 

func viewHandler(w http.ResponseWriter, r *http.Request, title string)
func editHandler(w http.ResponseWriter, r *http.Request, title string)
func saveHandler(w http.ResponseWriter, r *http.Request, title string)

Agora vamos definir uma função wrapper que recebe uma função do tipo acima, e retorna uma função do tipo http.HandlerFunc (adequada para ser passada à função http.HandleFunc): 

func makeHandler(fn func (http.ResponseWriter, *http.Request, string)) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        // Aqui vamos extrair o título da página da Request,
        // e chamar o handler fornecido 'fn'
    }
}

A função retornada é chamada de closure porque ela encapsula valores definidos fora dela. Neste caso, a variável fn (o único argumento de makeHandler) é encapsulada pelo closure. A variável fn será um dos nossos handlers save, edit ou view.

Agora podemos pegar o código de getTitle e usá-lo aqui (com algumas modificações menores):

{{code "final.go" `/func makeHandler/` `/^}/`}}

O closure retornado por makeHandler é uma função que recebe um http.ResponseWriter e http.Request (em outras palavras, um http.HandlerFunc). O closure extrai o title do caminho da requisição e o valida com a regexp validPath. Se o title for inválido, um erro será escrito no ResponseWriter usando a função http.NotFound. Se o title for válido, a função handler encapsulada fn será chamada com o ResponseWriter, Request e title como argumentos.

Agora podemos envolver as funções handler com makeHandler em main, antes de serem registradas com o package http:
