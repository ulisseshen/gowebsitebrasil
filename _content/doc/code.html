Introdução

Este documento demonstra o desenvolvimento de um pacote Go simples dentro de um módulo e introduz a ferramenta go, a maneira padrão de buscar, compilar e instalar módulos, pacotes e comandos Go.

Organização de código

Programas Go são organizados em pacotes. Um pacote é uma coleção de arquivos-fonte no mesmo diretório que são compilados juntos. Funções, tipos, variáveis e constantes definidos em um arquivo-fonte são visíveis para todos os outros arquivos-fonte dentro do mesmo pacote.

Um repositório contém um ou mais módulos. Um módulo é uma coleção de pacotes Go relacionados que são lançados juntos. Um repositório Go tipicamente contém apenas um módulo, localizado na raiz do repositório. Um arquivo chamado go.mod lá declara o caminho do módulo: o prefixo do caminho de importação para todos os pacotes dentro do módulo. O módulo contém os pacotes no diretório que contém seu arquivo go.mod, bem como subdiretórios desse diretório, até o próximo subdiretório contendo outro arquivo go.mod (se houver).

Note que você não precisa publicar seu código em um repositório remoto antes de poder compilá-lo. Um módulo pode ser definido localmente sem pertencer a um repositório. No entanto, é um bom hábito organizar seu código como se você fosse publicá-lo algum dia.

O caminho de cada módulo não só serve como um prefixo de caminho de importação para seus pacotes, mas também indica onde o comando go deve procurar para baixá-lo. Por exemplo, para baixar o módulo golang.org/x/tools, o comando go consultaria o repositório indicado por https://golang.org/x/tools (descrito com mais detalhes aqui).

Um caminho de importação é uma string usada para importar um pacote. O caminho de importação de um pacote é seu caminho de módulo unido com seu subdiretório dentro do módulo. Por exemplo, o módulo github.com/google/go-cmp contém um pacote no diretório cmp/. O caminho de importação desse pacote é github.com/google/go-cmp/cmp. Pacotes na biblioteca padrão não têm um prefixo de caminho de módulo.

Seu primeiro programa

Para compilar e executar um programa simples, primeiro escolha um caminho de módulo (usaremos example/user/hello) e crie um arquivo go.mod que o declare: 

$ mkdir hello # Alternativamente, clone-o se já existir em controle de versão.
$ cd hello
$ go mod init example/user/hello
go: creating new go.mod: module example/user/hello
$ cat go.mod
module example/user/hello

go 1.16
$

A primeira declaração em um arquivo-fonte Go deve ser package nome. Comandos executáveis devem sempre usar package main.

Em seguida, crie um arquivo chamado hello.go dentro desse diretório contendo o seguinte código Go: 

package main

import "fmt"

func main() {
    fmt.Println("Hello, world.")
}

Agora você pode compilar e instalar esse programa com a ferramenta go: 

$ go install example/user/hello
$

Este comando compila o comando hello, produzindo um binário executável. Ele então instala esse binário como $HOME/go/bin/hello (ou, no Windows, %USERPROFILE%\go\bin\hello.exe).

O diretório de instalação é controlado pelas variáveis de ambiente GOPATH e GOBIN. Se GOBIN estiver definido, binários são instalados nesse diretório. Se GOPATH estiver definido, binários são instalados no subdiretório bin do primeiro diretório na lista GOPATH. Caso contrário, binários são instalados no subdiretório bin do GOPATH padrão ($HOME/go ou %USERPROFILE%\go).

Você pode usar o comando go env para definir portavelmente o valor padrão para uma variável de ambiente para futuros comandos go: 

$ go env -w GOBIN=/somewhere/else/bin
$

Para desfazer a definição de uma variável previamente definida por go env -w, use go env -u: 

$ go env -u GOBIN
$

Comandos como go install se aplicam dentro do contexto do módulo que contém o diretório de trabalho atual. Se o diretório de trabalho não estiver dentro do módulo example/user/hello, go install pode falhar.

Por conveniência, comandos go aceitam caminhos relativos ao diretório de trabalho e usam o pacote no diretório de trabalho atual como padrão se nenhum outro caminho for fornecido. Então, em nosso diretório de trabalho, os seguintes comandos são todos equivalentes: 

$ go install example/user/hello

$ go install .

$ go install

Em seguida, vamos executar o programa para garantir que funcione. Para maior conveniência, adicionaremos o diretório de instalação ao nosso PATH para facilitar a execução de binários: 

# Usuários Windows devem consultar /wiki/SettingGOPATH
# para definir %PATH%.
$ export PATH=$PATH:$(dirname $(go list -f '{{"{{.Target}}"}}' .))
$ hello
Hello, world.
$

Se você estiver usando um sistema de controle de versão, agora seria um bom momento para inicializar um repositório, adicionar os arquivos e fazer commit da sua primeira alteração. Novamente, este passo é opcional: você não precisa usar controle de versão para escrever código Go. 

$ git init
Initialized empty Git repository in /home/user/hello/.git/
$ git add go.mod hello.go
$ git commit -m "initial commit"
[master (root-commit) 0b4507d] initial commit
 1 file changed, 7 insertion(+)
 create mode 100644 go.mod hello.go
$

O comando go localiza o repositório que contém um determinado caminho de módulo solicitando uma URL HTTPS correspondente e lendo metadados incorporados na resposta HTML (veja go help importpath). Muitos serviços de hospedagem já fornecem esses metadados para repositórios contendo código Go, então a maneira mais fácil de tornar seu módulo disponível para outros usarem é geralmente fazer com que seu caminho de módulo corresponda à URL do repositório.

Importando pacotes do seu módulo

Vamos escrever um pacote morestrings e usá-lo do programa hello. Primeiro, crie um diretório para o pacote chamado $HOME/hello/morestrings e, em seguida, um arquivo chamado reverse.go nesse diretório com o seguinte conteúdo: 

// Package morestrings implements additional functions to manipulate UTF-8
// encoded strings, beyond what is provided in the standard "strings" package.
package morestrings

// ReverseRunes returns its argument string reversed rune-wise left to right.
func ReverseRunes(s string) string {
    r := []rune(s)
    for i, j := 0, len(r)-1; i < len(r)/2; i, j = i+1, j-1 {
        r[i], r[j] = r[j], r[i]
    }
    return string(r)
}

Como nossa função ReverseRunes começa com uma letra maiúscula, ela é exportada, e pode ser usada em outros pacotes que importam nosso pacote morestrings.

Vamos testar se o pacote compila com go build: 

$ cd $HOME/hello/morestrings
$ go build
$

Isso não produzirá um arquivo de saída. Em vez disso, salva o pacote compilado no cache de build local.

Depois de confirmar que o pacote morestrings compila, vamos usá-lo do programa hello. Para fazer isso, modifique seu $HOME/hello/hello.go original para usar o pacote morestrings: 

package main

import (
    "fmt"

    "example/user/hello/morestrings"
)

func main() {
    fmt.Println(morestrings.ReverseRunes("!oG ,olleH"))
}

Instale o programa hello: 

$ go install example/user/hello

Executando a nova versão do programa, você deve ver uma nova mensagem invertida: 

$ hello
Hello, Go!

Importando pacotes de módulos remotos

Um caminho de importação pode descrever como obter o código-fonte do pacote usando um sistema de controle de revisão como Git ou Mercurial. A ferramenta go usa essa propriedade para buscar automaticamente pacotes de repositórios remotos. Por exemplo, para usar github.com/google/go-cmp/cmp em seu programa: 

package main

import (
    "fmt"

    "example/user/hello/morestrings"
    "github.com/google/go-cmp/cmp"
)

func main() {
    fmt.Println(morestrings.ReverseRunes("!oG ,olleH"))
    fmt.Println(cmp.Diff("Hello World", "Hello Go"))
}

Agora que você tem uma dependência em um módulo externo, precisa baixar esse módulo e registrar sua versão em seu arquivo go.mod. O comando go mod tidy adiciona requisitos de módulo ausentes para pacotes importados e remove requisitos em módulos que não são mais usados. 

$ go mod tidy
go: finding module for package github.com/google/go-cmp/cmp
go: found github.com/google/go-cmp/cmp in github.com/google/go-cmp v0.5.4
$ go install example/user/hello
$ hello
Hello, Go!
  string(
-     "Hello World",
+     "Hello Go",
  )
$ cat go.mod
module example/user/hello

go 1.16

require github.com/google/go-cmp v0.5.4
$

Dependências de módulo são automaticamente baixadas para o subdiretório pkg/mod do diretório indicado pela variável de ambiente GOPATH. O conteúdo baixado para uma versão específica de um módulo é compartilhado entre todos os outros módulos que fazem require dessa versão, então o comando go marca esses arquivos e diretórios como somente leitura. Para remover todos os módulos baixados, você pode passar o sinalizador -modcache para go clean: 

$ go clean -modcache
$

Testando

Go tem um framework de teste leve composto pelo comando go test e o pacote testing.

Você escreve um teste criando um arquivo com um nome terminando em _test.go que contém funções chamadas TestXXX com assinatura func (t *testing.T). O framework de teste executa cada uma dessas funções; se a função chama uma função de falha como t.Error ou t.Fail, o teste é considerado como tendo falhado.

Adicione um teste ao pacote morestrings criando o arquivo $HOME/hello/morestrings/reverse_test.go contendo o seguinte código Go. 

package morestrings

import "testing"

func TestReverseRunes(t *testing.T) {
    cases := []struct {
        in, want string
    }{
        {"Hello, world", "dlrow ,olleH"},
        {"Hello, 世界", "界世 ,olleH"},
        {"", ""},
    }
    for _, c := range cases {
        got := ReverseRunes(c.in)
        if got != c.want {
            t.Errorf("ReverseRunes(%q) == %q, want %q", c.in, got, c.want)
        }
    }
}

Em seguida, execute o teste com go test: 

$ cd $HOME/hello/morestrings
$ go test
PASS
ok  	example/user/hello/morestrings 0.165s
$

Execute go help test e veja a documentação do pacote testing para mais detalhes.
