Este tópico descreve como construir e executar Go a partir do código fonte. Para instalar com um instalador, veja Download e instalação.

Introdução

Go é um projeto open source, distribuído sob uma licença estilo BSD. Este documento explica como fazer checkout dos fontes, construí-los em sua própria máquina, e executá-los.

A maioria dos usuários não precisa fazer isso, e em vez disso instalará a partir de packages binários pré-compilados conforme descrito em Download e instalação, um processo muito mais simples. Se você quer ajudar a desenvolver o que vai naqueles packages pré-compilados, no entanto, continue lendo.

Existem duas toolchains oficiais de compilador Go. Este documento foca no compilador e ferramentas gc Go. Para informações sobre como trabalhar no gccgo, um compilador mais tradicional usando o back end GCC, veja Configurando e usando gccgo.

Os compiladores Go suportam os seguintes conjuntos de instruções:

amd64, 386
O conjunto de instruções x86, 64- e 32-bit.
arm64, arm
O conjunto de instruções ARM, 64-bit (AArch64) e 32-bit.
loong64
O conjunto de instruções LoongArch de 64-bit.
mips64, mips64le, mips, mipsle
O conjunto de instruções MIPS, big- e little-endian, 64- e 32-bit.
ppc64, ppc64le
O conjunto de instruções PowerPC de 64-bit, big- e little-endian.
riscv64
O conjunto de instruções RISC-V de 64-bit.
s390x
A IBM z/Architecture.
wasm
WebAssembly.

Os compiladores podem ter como alvo os sistemas operacionais AIX, Android, DragonFly BSD, FreeBSD, Illumos, Linux, macOS/iOS (Darwin), NetBSD, OpenBSD, Plan 9, Solaris, e Windows (embora nem todos os sistemas operacionais suportem todas as arquiteturas).

Uma lista de ports que são considerados "first class" está disponível na página wiki first class ports.

O conjunto completo de combinações suportadas está listado na discussão de variáveis de ambiente abaixo.

Veja a página MinimumRequirements do Go Wiki para os requisitos gerais de sistema.

Instalar binários do compilador Go para bootstrap

A toolchain Go é escrita em Go. Para construí-la, você precisa de um compilador Go instalado. Os scripts que fazem a build inicial das ferramentas procuram por um comando "go" em $PATH, então contanto que você tenha Go instalado em seu sistema e configurado em seu $PATH, você está pronto para construir Go do fonte. Ou se você preferir pode definir $GOROOT_BOOTSTRAP para a raiz de uma instalação Go para usar para construir a nova toolchain Go; $GOROOT_BOOTSTRAP/bin/go deve ser o comando go a usar.

A versão mínima de Go requerida depende da versão alvo de Go:

  • Go <= 1.4: uma toolchain C.
  • 1.5 <= Go <= 1.19: um compilador Go 1.4.
  • 1.20 <= Go <= 1.21: um compilador Go 1.17.
  • 1.22 <= Go <= 1.23: um compilador Go 1.20.
  • Indo adiante, Go versão 1.N requererá um compilador Go 1.M, onde M é N-2 arredondado para baixo para um número par. Exemplo: Go 1.24 e 1.25 requerem Go 1.22.

Existem quatro formas possíveis de obter uma toolchain bootstrap:

  • Baixar uma release binária recente de Go.
  • Fazer cross-compile de uma toolchain usando um sistema com uma instalação Go funcionando.
  • Usar gccgo.
  • Compilar uma toolchain do Go 1.4, a última release Go com um compilador escrito em C.

Essas abordagens são detalhadas abaixo.

Toolchain bootstrap de release binária

Para usar uma release binária como uma toolchain bootstrap, veja a página de downloads ou use qualquer outra distribuição Go empacotada que atenda os requisitos mínimos de versão.

Toolchain bootstrap de código cross-compilado

Para fazer cross-compile de uma toolchain bootstrap do fonte, o que é necessário em sistemas que Go 1.4 não tinha como alvo (por exemplo, linux/ppc64le), instale Go em um sistema diferente e execute bootstrap.bash.

Quando executado como (por exemplo) 

$ GOOS=linux GOARCH=ppc64 ./bootstrap.bash

bootstrap.bash faz cross-compile de uma toolchain para aquela combinação GOOS/GOARCH, deixando a árvore resultante em ../../go-${GOOS}-${GOARCH}-bootstrap. Essa árvore pode ser copiada para uma máquina do tipo alvo dado e usada como GOROOT_BOOTSTRAP para fazer bootstrap de uma build local.

Toolchain bootstrap usando gccgo

Para usar gccgo como toolchain bootstrap, você precisa arranjar para que $GOROOT_BOOTSTRAP/bin/go seja a ferramenta go que vem como parte do gccgo 5. Por exemplo no Ubuntu Vivid: 

$ sudo apt-get install gccgo-5
$ sudo update-alternatives --set go /usr/bin/go-5
$ GOROOT_BOOTSTRAP=/usr ./make.bash

Toolchain bootstrap de código fonte C

Para construir uma toolchain bootstrap de código fonte C, use ou o branch git release-branch.go1.4 ou go1.4-bootstrap-20171003.tar.gz, que contém o código fonte Go 1.4 mais correções acumuladas para manter as ferramentas rodando em sistemas operacionais mais novos. (Go 1.4 foi a última distribuição em que a toolchain foi escrita em C.) Após desempacotar o fonte Go 1.4, cd para o subdiretório src, defina CGO_ENABLED=0 no ambiente, e execute make.bash (ou, no Windows, make.bat).

Uma vez que o fonte Go 1.4 tenha sido desempacotado em seu diretório GOROOT_BOOTSTRAP, você deve manter esta instância de clone git com checkout para o branch release-branch.go1.4. Especificamente, não tente reusar este clone git no passo posterior chamado "Fetch the repository." A toolchain bootstrap go1.4 deve ser capaz de atravessar apropriadamente os fontes go1.4 que ela assume estarem presentes sob esta raiz de repositório.

Note que Go 1.4 não roda em todos os sistemas em que versões posteriores de Go rodam. Em particular, Go 1.4 não suporta versões atuais de macOS. Em tais sistemas, a toolchain bootstrap deve ser obtida usando um dos outros métodos.

Instalar Git, se necessário

Para executar o próximo passo você deve ter Git instalado. (Verifique que você tem um comando git antes de prosseguir.)

Se você não tem uma instalação Git funcionando, siga as instruções na página Git downloads.

(Opcional) Instalar um compilador C

Para construir uma instalação Go com cgo suporte, que permite programas Go importarem bibliotecas C, um compilador C como gcc ou clang deve ser instalado primeiro. Faça isso usando qualquer método de instalação que seja padrão no sistema.

Para construir sem cgo, defina a variável de ambiente CGO_ENABLED=0 antes de executar all.bash ou make.bash.

Fazer fetch do repositório

Mude para o diretório onde você pretende instalar Go, e certifique-se de que o diretório goroot não existe. Então clone o repositório e faça checkout da última tag de release ou branch de release (go1.22.0, ou release-branch.go1.22, por exemplo):

$ git clone https://go.googlesource.com/go goroot
$ cd goroot
$ git checkout <tag>

Onde <tag> é a string de versão da release.

Go será instalado no diretório onde é feito checkout. Por exemplo, se Go é feito checkout em $HOME/goroot, executáveis serão instalados em $HOME/goroot/bin. O diretório pode ter qualquer nome, mas note que se Go é feito checkout em $HOME/go, ele entrará em conflito com a localização padrão de $GOPATH. Veja GOPATH abaixo.

Lembrete: Se você optou por também compilar os binários bootstrap do fonte (em uma seção anterior), você ainda precisa fazer git clone novamente neste ponto (para fazer checkout da última <tag>), porque você deve manter seu repositório go1.4 distinto.

(Opcional) Mudar para o branch master

Se você pretende modificar o código fonte go, e contribuir suas mudanças para o projeto, então mova seu repositório para fora da tag de release, e para o branch master (de desenvolvimento). Caso contrário, pule este passo.

$ git checkout master

Instalar Go

Para construir a distribuição Go, execute 

$ cd src
$ ./make.bash

(Para construir no Windows use make.bat.)

Se tudo correr bem, ele terminará imprimindo saída como: 

---
Installed Go for linux/amd64 in /home/you/go.
Installed commands in /home/you/go/bin.
*** You need to add /home/you/go/bin to your $PATH. ***

onde os detalhes nas últimas linhas refletem o sistema operacional, arquitetura, e diretório raiz usados durante a instalação.

Para mais informações sobre formas de controlar a build, veja a discussão de variáveis de ambiente abaixo. Você também pode executar all.bash (ou all.bat) para executar testes importantes para Go, o que pode levar mais tempo que simplesmente construir Go.

Testando sua instalação

Verifique que Go está instalado corretamente construindo um programa simples.

Crie um arquivo chamado hello.go e coloque o seguinte programa nele: 

package main

import "fmt"

func main() {
	fmt.Printf("hello, world\n")
}

Então execute-o com a ferramenta go: 

$ go run hello.go
hello, world

Se você vir a mensagem "hello, world" então Go está instalado corretamente.

Configure seu ambiente de trabalho

Você está quase lá. Você só precisa fazer um pouco mais de configuração.

Como Escrever Código Go Aprenda como configurar e usar as ferramentas Go

O documento Como Escrever Código Go fornece instruções de configuração essenciais para usar as ferramentas Go.

Instalar ferramentas adicionais

O código fonte para várias ferramentas Go (incluindo gopls) é mantido em o repositório golang.org/x/tools. Para instalar uma das ferramentas (gopls neste caso): 

$ go install golang.org/x/tools/gopls@latest

Recursos da comunidade

Os recursos usuais da comunidade listados na página de ajuda têm desenvolvedores ativos que podem ajudá-lo com problemas com sua instalação ou seu trabalho de desenvolvimento. Para aqueles que desejam se manter atualizados, existe outra lista de email, golang-checkins, que recebe uma mensagem resumindo cada checkin no repositório Go.

Bugs podem ser reportados usando o rastreador de issues Go.

Acompanhando releases

Novas releases são anunciadas na lista de email golang-announce. Cada anúncio menciona a última tag de release, por exemplo, go1.9.

Para atualizar uma árvore existente para a última release, você pode executar: 

$ cd go/src
$ git fetch
$ git checkout <tag>
$ ./all.bash

Onde <tag> é a string de versão da release.

Variáveis de ambiente opcionais

O ambiente de compilação Go pode ser customizado por variáveis de ambiente. Nenhuma é requerida pela build, mas você pode querer definir algumas para sobrescrever os padrões.

  • $GOROOT

    A raiz da árvore Go, frequentemente $HOME/go1.X. Seu valor é construído na árvore quando ela é compilada, e assume como padrão o pai do diretório onde all.bash foi executado. Não há necessidade de definir isso a menos que você queira alternar entre múltiplas cópias locais do repositório.

  • $GOROOT_FINAL

    O valor assumido por binários e scripts instalados quando $GOROOT não está definido explicitamente. Assume como padrão o valor de $GOROOT. Se você quer construir a árvore Go em uma localização mas movê-la para outro lugar após a build, defina $GOROOT_FINAL para a localização eventual.

  • $GOPATH

    O diretório onde projetos Go fora da distribuição Go são tipicamente feitos checkout. Por exemplo, golang.org/x/tools pode ter checkout feito para $GOPATH/src/golang.org/x/tools. Executáveis fora da distribuição Go são instalados em $GOPATH/bin (ou $GOBIN, se definido). Módulos são baixados e cacheados em $GOPATH/pkg/mod.

    A localização padrão de $GOPATH é $HOME/go, e normalmente não é necessário definir GOPATH explicitamente. No entanto, se você fez checkout da distribuição Go para $HOME/go, você deve definir GOPATH para outra localização para evitar conflitos.

  • $GOBIN

    O diretório onde executáveis fora da distribuição Go são instalados usando o comando go. Por exemplo, go install golang.org/x/tools/gopls@latest baixa, constrói, e instala $GOBIN/gopls. Por padrão, $GOBIN é $GOPATH/bin (ou $HOME/go/bin se GOPATH não está definido). Após instalar, você vai querer adicionar este diretório ao seu $PATH para poder usar ferramentas instaladas.

    Note que os executáveis da distribuição Go são instalados em $GOROOT/bin (para executáveis invocados por pessoas) ou $GOTOOLDIR (para executáveis invocados pelo comando go; assume como padrão $GOROOT/pkg/$GOOS_$GOARCH) em vez de $GOBIN.

  • $GOOS e $GOARCH

    O nome do sistema operacional alvo e arquitetura de compilação. Estes assumem como padrão os valores de $GOHOSTOS e $GOHOSTARCH respectivamente (descritos abaixo).

    Escolhas para $GOOS são android, darwin, dragonfly, freebsd, illumos, ios, js, linux, netbsd, openbsd, plan9, solaris, wasip1, e windows.

    Escolhas para $GOARCH são amd64 (x86 64-bit, o port mais maduro), 386 (x86 32-bit), arm (ARM 32-bit), arm64 (ARM 64-bit), ppc64le (PowerPC 64-bit, little-endian), ppc64 (PowerPC 64-bit, big-endian), mips64le (MIPS 64-bit, little-endian), mips64 (MIPS 64-bit, big-endian), mipsle (MIPS 32-bit, little-endian), mips (MIPS 32-bit, big-endian), s390x (IBM System z 64-bit, big-endian), e wasm (WebAssembly 32-bit).

  • $GOHOSTOS e $GOHOSTARCH

    O nome do sistema operacional host e arquitetura de compilação. Estes assumem como padrão o sistema operacional e arquitetura do sistema local.

    Escolhas válidas são as mesmas que para $GOOS e $GOARCH, listadas acima. Os valores especificados devem ser compatíveis com o sistema local. Por exemplo, você não deve definir $GOHOSTARCH para arm em um sistema x86.

  • $GO386 (apenas para 386, assume como padrão sse2)

    Esta variável controla como gc implementa computações de ponto flutuante.

    • GO386=softfloat: usa operações de ponto flutuante de software; deve suportar todos os chips x86 (Pentium MMX ou posterior).
    • GO386=sse2: usa SSE2 para operações de ponto flutuante; tem melhor desempenho mas apenas disponível em Pentium 4/Opteron/Athlon 64 ou posterior.
  • $GOARM (apenas para arm; padrão é auto-detectado se construindo no processador alvo, 7 se não)

    Isso define a versão da arquitetura do co-processador de ponto flutuante ARM que o runtime deve ter como alvo. Se você está compilando no sistema alvo, seu valor será auto-detectado.

    • GOARM=5: usa ponto flutuante de software; quando CPU não tem co-processador VFP
    • GOARM=6: usa apenas VFPv1; padrão se fazendo cross compile; geralmente cores ARM11 ou melhores (VFPv2 ou melhor também é suportado)
    • GOARM=7: usa VFPv3; geralmente cores Cortex-A

    Se em dúvida, deixe esta variável não definida, e ajuste-a se requerido quando você primeiro executar o executável Go. A página GoARM na wiki da comunidade Go contém detalhes adicionais sobre o suporte ARM do Go.

  • $GOAMD64 (apenas para amd64; padrão é v1)

    Isso define o nível de microarquitetura para o qual compilar. Valores válidos são v1 (padrão), v2, v3, v4. Veja a página do wiki Go MinimumRequirements para mais informações.

  • $GOMIPS (para mips e mipsle apenas)
    $GOMIPS64 (para mips64 e mips64le apenas)

    Estas variáveis definem se usar instruções de ponto flutuante. Defina como "hardfloat" para usar instruções de ponto flutuante; este é o padrão. Defina como "softfloat" para usar ponto flutuante soft.

  • $GOPPC64 (para ppc64 e ppc64le apenas)

    Esta variável define o nível de processador (i.e. versão da Instruction Set Architecture) para o qual o compilador terá como alvo. O padrão é power8.

    • GOPPC64=power8: gera instruções ISA v2.07
    • GOPPC64=power9: gera instruções ISA v3.00
  • $GORISCV64 (apenas para riscv64)

    Esta variável define o perfil de aplicação user-mode RISC-V para o qual compilar. O padrão é rva20u64.

    • GORISCV64=rva20u64: usa apenas extensões RISC-V que são obrigatórias no perfil RVA20U64
    • GORISCV64=rva22u64: usa apenas extensões RISC-V que são obrigatórias no perfil RVA22U64
    • GORISCV64=rva23u64: usa apenas extensões RISC-V que são obrigatórias no perfil RVA23U64
  • $GOWASM (apenas para wasm)

    Esta variável é uma lista separada por vírgulas de features experimentais WebAssembly que o binário WebAssembly compilado tem permissão para usar. O padrão é não usar features experimentais.

    • GOWASM=satconv: gera conversões saturating (non-trapping) float-to-int
    • GOWASM=signext: gera operadores sign-extension

Note que $GOARCH e $GOOS identificam o ambiente alvo, não o ambiente em que você está rodando. Efetivamente, você está sempre fazendo cross-compile. Por arquitetura, queremos dizer o tipo de binários que o ambiente alvo pode executar: um sistema x86-64 rodando um sistema operacional apenas 32-bit deve definir GOARCH para 386, não amd64.

Se você escolher sobrescrever os padrões, defina estas variáveis em seu perfil de shell ($HOME/.bashrc, $HOME/.profile, ou equivalente). As configurações podem parecer algo como isto: 

export GOARCH=amd64
export GOOS=linux

embora, para reiterar, nenhuma destas variáveis precisa ser definida para construir, instalar, e desenvolver a árvore Go.
